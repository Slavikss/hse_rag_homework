# RAG по финансовой отчётности — Вячеслав Гуч

Решение задания: поиск и ответы по 55 PDF (3925 страниц), включая сканы. Ветка `vyacheslav_guch_main`. Исходные условия и критерии сохранены в [ASSIGNMENT.md](ASSIGNMENT.md).

## Как работает

1. `rag/prepare.py` извлекает текст PyMuPDF с пространственным расположением таблиц. Страницы без текста проходят Tesseract (`rus+eng`, 240 dpi); OCR сохраняет координаты слов. Каждый фрагмент хранит исходные `doc_id` и номер PDF-страницы с 1.
2. Страницы разбиваются на фрагменты до 2800 символов с перекрытием 500. Эмбеддинги сервиса преподавателя нормализуются; cosine similarity считается NumPy. BM25 со стеммингом-префиксом дополняет векторный поиск; результаты объединяются Reciprocal Rank Fusion.
3. LLM-планировщик разбивает составные вопросы на запросы и выбирает отчёты по организации и периоду. Поиск возвращает полные страницы и продолжения наиболее релевантных таблиц. Единицы измерения, объявленные в начале каждого отчета, передаются вместе с цитатой из PDF; явные локальные единицы имеют приоритет.
4. Агент проверяет достаточность доказательств и **сам решает**, нужен ли дополнительный поиск или чтение соседних страниц. Максимум три итерации. Числовая проверка сохраняет первую страницу гибридного поиска, если на ней явно найдено число итогового ответа; это защищает источники от потери при разрывах строк OCR. Итоговый ответ содержит только проверенные источники; несуществующие/непрочитанные ссылки отбрасываются. Решения агента сохраняются в `agent_steps` и трассах LangSmith.
5. Оценка использует неизменённые `score_context` и `score_answer` из `eval/eval_functions.py`: исходные модель `deepseek-flash` и промпт судьи. Время измеряется от передачи вопроса готовому RAG до полного ответа, включая планирование, эмбеддинги и повторный поиск; загрузка индекса и судья в него не входят.

RAG читает только каталог и PDF-производный индекс. `train.jsonl`, `test.jsonl`, `gold_context`, `gold_answer` доступны исключительно оценщику. Готовые ответы не кешируются и не воспроизводятся вместо нового прогона.

## Установка

Python 3.12, Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.lock
cp .env.example .env
```

Заполнить `LLM_API_KEY`, `EMB_KEY`, `LANGSMITH_API_KEY` в `.env`. Ключи не входят в git. `LLM_MODEL=deepseek-flash`; адреса сервисов заданы в примере. Для LangSmith нужен доступ к соответствующему workspace. `LLM_RPM=10` задает общий лимит вызовов генерации и неизмененного официального судьи; индексатор соблюдает лимит сервиса эмбеддингов 60 запросов в минуту. Не запускайте несколько eval-процессов одновременно с одним ключом.

## Индекс

Для воспроизводимой проверки используется PDF-производный `results/knowledge_index.zip`: RAG автоматически распакует его в `index/`, если индекс ещё не установлен. В архиве только тексты страниц, фрагменты, эмбеддинги и описание индекса, без вопросов и ответов датасета.

Для полного построения с нуля:

```bash
sudo apt-get install tesseract-ocr tesseract-ocr-rus tesseract-ocr-eng
LANGSMITH_TRACING=false python -m rag.prepare --workers 8
python scripts/package_index.py
```

Скрипт автоматически скачивает и распаковывает отчёты. При повторном запуске использует уже распознанные документы и эмбеддинги по SHA256 текста. Исходные сканы и технический кеш не входят в сдачу.

## Итоговая оценка

```bash
OPENBLAS_NUM_THREADS=1 python scripts/run_eval.py data/test.jsonl --output results/test_results.xlsx --workers 4 --langsmith
```

Все 141 вопрос получают **новые** ответы и оценки. `--langsmith` создаёт отдельные dataset и experiment с вложенными трассами планирования, поиска и генерации и четырьмя метриками. Ссылки записываются в `results/test_results.langsmith.json`. Публичный dataset позволяет преподавателю открыть эксперимент, публичные трассы приведены отдельно.

Excel содержит листы «Итоги» и «По вопросам», десять обязательных колонок и объяснение судьи. Полные ответы, решения агента и измерения также записываются в JSONL; средние — в `.summary.json`. При сетевом сбое можно продолжить незавершённый локальный прогон с `--resume` (без `--langsmith`); обычная команда всегда считает заново.

Отладка на train:

```bash
python scripts/run_eval.py data/train.jsonl --limit 12 --output outputs/train_smoke.xlsx --workers 4
python -m pytest -q
```

Также сохранён совместимый интерфейс `from eval.rag_example import RAG; RAG().rag(question)` и исходный последовательный `python -m eval.evaluator_excel data/test.jsonl`.

## Воспроизводимость

Зафиксированы версии библиотек, индекс, промпты и `temperature=0`. Повторная проверка должна использовать тот же индекс, модель, шлюз и `--workers 4`. Сервисы внешние: задержка сети, очередь и изменения модели могут изменить результат. Время не подменяется кешем и не выравнивается искусственными паузами; требование задания об отклонении среднего времени не более 5% нельзя гарантировать для внешнего API.
