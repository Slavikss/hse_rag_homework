RAG по финансовой отчётности. Вячеслав Гуч.

Система отвечает на вопросы по 55 финансовым отчётам. Всего в корпусе 3925 страниц, из них 381 пришлось распознать через OCR. Для сдачи используется ветка vyacheslav_guch_main.

Итоговый прогон на всех 141 вопросах test сейчас выполняется. После его завершения здесь будут указаны средние context_recall, context_precision, answer_correctness и время ответа в секундах. Результаты сохраняются в results/test_results.xlsx. В Excel есть сводка и отдельная строка для каждого вопроса со всеми десятью обязательными полями и объяснением судьи.

Сначала PyMuPDF извлекает текст из PDF, сохраняя расположение строк и числовых колонок. Если на странице нет текстового слоя, используется Tesseract с русским и английским языками, разрешением 240 dpi и координатами распознанных слов. У каждой страницы остаются исходный doc_id и номер страницы PDF, начиная с единицы.

Текст разбит на 8683 фрагмента длиной до 2800 символов с перекрытием 500 символов. Для них рассчитаны штатные эмбеддинги сервиса преподавателя размерности 1024. Поиск объединяет близость эмбеддингов и BM25 через Reciprocal Rank Fusion. В ответ на запрос модель получает полные страницы, а не только обрезанные фрагменты. Для самых подходящих страниц также читается продолжение таблицы. Если единицы не повторяются в примечании, они берутся из заголовка того же отчёта; явные единицы конкретной таблицы имеют приоритет.

Агент разбирает вопрос на поисковые запросы, выбирает отчёты по организации и периоду и оценивает найденные сведения. Если их не хватает, он сам решает повторить поиск или прочитать соседние страницы. Ограничение — три итерации. Ответ и ссылки формируются по найденным документам. Для числовых ответов дополнительно проверяется первая страница поиска: если на ней есть число ответа, ссылка сохраняется. Это помогает не терять подходящий источник из-за разрывов строк при OCR. Текст ответа приводится к обычным абзацам без Markdown; числа, знаки и единицы при этом не меняются.

RAG читает только каталог документов и индекс, построенный по PDF. Эталонные ответы и страницы из train и test поступают только в оценщик. Готовые ответы не кешируются. Каждый обычный запуск eval заново выполняет поиск, генерацию и оценку.

Для установки нужны Python 3.12 и зависимости из requirements.lock. В работе используются PyMuPDF, NumPy, rank-bm25, requests, python-dotenv, openpyxl и LangSmith. Из корня репозитория выполните следующие команды, каждую с новой строки:

python3 -m venv .venv

source .venv/bin/activate

pip install -r requirements.lock

cp .env.example .env

В .env нужно заполнить LLM_API_KEY, EMB_KEY и LANGSMITH_API_KEY. Адреса сервисов и модель deepseek-flash уже указаны в примере. Для воспроизводимого запуска оставьте LLM_RPM=10. Генерация и судья используют общую очередь запросов, а индексатор соблюдает лимит сервиса эмбеддингов в 60 запросов в минуту. Несколько eval-процессов с одним ключом одновременно запускать не стоит. Файл .env исключён из git, ключей в сдаче нет.

Готовый индекс лежит в results/knowledge_index.zip. Если папки index ещё нет, RAG распакует архив автоматически. В нём только тексты PDF, фрагменты, эмбеддинги и описание параметров индекса. Вопросов датасета и подготовленных ответов в архиве нет.

Для итоговой проверки запустите:

LLM_RPM=10 OPENBLAS_NUM_THREADS=1 python scripts/run_eval.py data/test.jsonl --output results/test_results.xlsx --workers 4 --langsmith

Этот запуск создаёт Excel, подробный JSONL, файл со средними метриками и эксперимент LangSmith с вложенными трассами планирования, поиска и генерации. Ссылки записываются в results/test_results.langsmith.json. Публичный dataset открывает доступ к эксперименту без ключа; несколько трасс доступны отдельно. Проверить публичный доступ можно командой python scripts/check_public_experiment.py.

Судья и функции оценки взяты из eval/eval_functions.py без изменений. Используются заданные модель deepseek-flash и промпт преподавателя. Время измеряется от передачи вопроса готовому RAG до полного ответа, включая планирование и дополнительный поиск. Загрузка индекса и оценка судьёй в это время не входят. Версии библиотек, индекс, промпты, temperature=0, число потоков и лимит запросов зафиксированы. При этом задержка внешнего API может меняться, поэтому требование о совпадении среднего времени с точностью до 5% нельзя гарантировать. Паузы для искусственного выравнивания времени не используются.

Успешные результаты записываются сразу. Если прогон прервался из-за сети, его можно продолжить с параметром --resume. Если включён --langsmith, продолжение использует тот же dataset и эксперимент. Этот режим пропускает уже выполненные вопросы и нужен только для восстановления. После ответа 429 вся очередь выдерживает общую паузу, чтобы дождаться сброса ограничения шлюза. Для повторной проверки качества следует использовать обычную команду выше.

Для отладки на первых 12 вопросах train можно выполнить python scripts/run_eval.py data/train.jsonl --limit 12 --output outputs/train_smoke.xlsx --workers 4. Проверки кода запускаются командой python -m pytest -q. Также сохранён исходный интерфейс RAG().rag(question) через eval/rag_example.py и последовательный оценщик python -m eval.evaluator_excel data/test.jsonl.

Если нужно полностью пересобрать индекс, установите Tesseract командой sudo apt-get install tesseract-ocr tesseract-ocr-rus tesseract-ocr-eng, затем запустите LANGSMITH_TRACING=false python -m rag.prepare --workers 8. Скрипт сам скачает отчёты, распознает страницы и рассчитает эмбеддинги. Уже обработанные документы и эмбеддинги сохраняются в кеше. При лимите 60 запросов в минуту полная сборка занимает около двух с половиной часов. Команда python scripts/package_index.py обновляет архив для сдачи.
